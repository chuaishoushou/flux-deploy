第一部分：IDEA 插件使用

1.1 插件概述与功能特性

FLUX 客服更新插件是 IntelliJ IDEA 集成工具，让开发人员可以在 IDE 中直接将代码变更部署到客户 FTP 或本地包，实现零切换的开发体验。

功能说明
工程树形选择点击工程下拉框，树形展示所有 Maven 模块，单击叶子节点选中
两种更新模式整包更新 / 增量更新（Git 变更默认勾选 + 用户可调）
文件树形勾选多级目录树，支持全选/单选，显示「已选 N / 总数 M」
FTP 三级联动项目 → 系统 → 目标包，自动精确匹配产物
WAR lib 对齐全量更新 WAR 时自动以远程包的 WEB-INF/lib 为准
多主目标同名 JAR 跨子目录并行备份/加锁/上传，互不干扰
本地模式不登录 FTP，直接对本地 jar/war 打补丁输出新包
安全部署流程备份 → 加锁 → 上传 → SHA256 校验 → 解锁
一键回滚失败自动回滚，成功后可手动回滚到备份版本
实时日志 + 文件保存实时输出，按日期保存到 .flux-deploy-log/

1.2 插件安装与首次使用

安装步骤

  1. 获取插件 ZIP 包：flux-deploy-plugin-1.2.3.zip
  2. IDEA → Settings → Plugins → ⚙ → Install Plugin from Disk
  3. 选择 ZIP 文件，重启 IDEA
  4. 右侧栏出现「FLUX 客服更新」工具窗口

首次连接 FTP

点「账号 ▾ → 添加新账号」，输入：

字段示例说明
主机47.102.153.34FTP 服务器 IP 或域名
端口18080默认 FTP 端口
用户名xumanyiFTP 账号
密码********AES-256-GCM 加密保存

连接成功后凭据自动保存到 ~/.flux-deploy/credentials.toml，后续无需再次输入。

1.3 三种使用入口

入口位置说明
工具窗口右侧栏「FLUX 客服更新」常规入口，完整面板
右键菜单项目树中右键 Maven 模块或具体文件快速触发并自动预选
本地模式工具窗口切换到「本地模式」对本地 jar/war 打补丁，不登录 FTP

右键菜单项

菜单项切换到的模式触发条件预填行为
整包更新FULL右键模块目录—
自动检测INCREMENTAL右键模块目录自动跑 Git 检测，把变更项默认勾选
手动选择INCREMENTAL右键具体文件把右键选中的文件预先勾选
打开更新面板-任何位置—

「自动检测」与「手动选择」都进入同一个增量更新模式，只是两种快捷预填方式。进面板后用户仍可任意调整勾选。

1.4 主面板布局

面板分四个区域，从上到下：源 → 目标 → 信息 → 按钮栏，底部是日志区。

源 Section

控件操作说明
工程下拉框点击弹出树树形展示所有 Maven 模块，单击叶子选中
产物显示自动从 pom.xml 解析，优先扫描 target/ 实际产物
更新模式下拉选择整包更新 / 增量更新
文件树勾选多级目录树，右上角显示「已选 N / 总数 M」
全选 / 刷新勾选 / 点 ↻一键全选；刷新按当前模式重新扫描

文件状态标识：[A] 新增（绿色）、[M] 修改（蓝色）、[D] 删除（橙色）。

目标 Section

控件操作说明

项目下拉框下拉对应 /开发/{项目}/，支持搜索
系统下拉框下拉对应 /开发/{项目}/{系统}/
目标包树勾选列出 JAR/WAR；与源产物同名的包自动勾选并锁定
全选 WAR勾选一键勾选所有 WAR（用于 JAR 嵌入更新）
刷新 ↻点击重连 FTP + 按当前层级重新拉取

产物匹配规则：本地产物文件名必须与远程包完全一致（含版本号）。不同版本不会自动匹配。

信息 Section

字段必填说明

客服号同上示例 20260328155300000001A
开发勾选备份或版本记录时必填英文 ID，如 xumanyi；自动缓存上次值

按钮栏与日志

按钮位置功能
预检左仅检查 FTP 状态和远端包，不编译、不上传、不修改
打包并上传左完整执行：编译 → 备份 → 加锁 → 上传 → SHA256 校验 → 解锁
回滚左恢复上次备份版本；仅成功部署后可用，回滚后置灰

1.5 更新模式（整包 / 增量）

v1.1.2 起，更新模式从原来的三档（整包 / 手动选择 / 自动检测变更）合并为两档。「文件来源」（手选 / Git 检测）不再是模式选项，而是同一个「增量更新」模式下的两种预填方式。

整包更新（FULL）

mvn clean package 编译整个模块，完整替换远程包。

  • 适用：大版本更新、整体变更
  • WAR 特殊处理：自动以远程 WEB-INF/lib 为准对齐
  • 无文件清单：选这个模式后右侧只展示「将替换整个远程包」提示

增量更新（INCREMENTAL）

列出模块下全部可部署文件，Git 变更项默认勾选，用户可在此基础上自由增删勾选。

  • 适用：日常迭代、针对性 bug 修复
  • 状态标识：[A] 新增（绿）、[M] 修改（蓝）、[D] 删除（橙）
  • 三种快捷入口都进这个模式：
    • 下拉切换 → 默认按 Git 变更勾选
    • 右键模块「自动检测」→ 同上，等价于直接进面板
    • 右键文件「手动选择」→ 把右键选中的文件预先勾选
  • 所有勾选都可以人工再调整（取消默认勾选 / 加 Git 没识别到的文件）

刷新按钮

「更新模式」下拉右侧的 ↻ 按钮，点击后根据当前模式重新拉取：

  • 整包更新：仅输出提示（无列表可刷新）
  • 增量更新：重新扫描模块文件 + 重跑 Git 变更检测；用户已勾选项会被尽量保留（仍存在于扫描结果的）

1.6 备份与回滚

勾选「执行备份」后，上传前会把远端原包备份到 backup/yyyyMMdd_{开发}/。更新失败会自动回滚。更新成功后「回滚」按钮可用，可手动回滚到备份版本。

⚠ 不备份的情况下失败无法自动恢复，请谨慎使用。

安全机制一览

机制作用实现
备份恢复点加锁前自动备份到 backup/YYYYMMDD_op/，保留相对目录结构
文件锁防并发rename 为 __LOCK__ 格式
SHA256完整性上传后重新下载比对哈希
自动回滚失败恢复任何步骤失败自动从备份恢复
路径校验防误操作必须在 /开发/ 下，禁止 ..
线程安全连接稳定FTP 操作加锁串行化
凭据加密密码安全AES-256-GCM 加密存储

1.7 本地模式

用户手里有一个本地 jar/war 包，想把本地编译的变更打进去，输出新包。不登录 FTP、不备份、不写版本记录、不可回滚。

三种分流

按「源工程产物类型 × 用户提供包类型」自动判定：

  • jar → jar：源工程 jar 模块，用户提供 jar 包；校验包名前缀 + 版本号严格一致后直接替换 jar 内条目。
  • war → war：源工程 war 模块，用户提供 war 包；校验后替换 WEB-INF/classes/ 下的类。
  • jar → war/lib：源工程 jar，用户提供 war 包；在 WEB-INF/lib/ 下定位匹配的 jar，版本严格一致后抽出 → 打补丁 → 回写 war。

输出与交互

  • 默认输出到 <包所在目录>/patched_{yyyyMMdd_HHmmss}/，同名文件。可手动改。
  • 支持从 Finder 或项目树 拖拽 jar/war 进来
  • 点「本地打包」先预检 → 弹出变更清单（修改/新增/删除）→ 确认后编译 + 打包
  • 成功后弹卡片：打开所在目录 / 复制路径 / 关闭

1.8 前置校验

点击打包并上传或打包不上传按钮时，插件会先做一次硬性前置校验。以下任一条件缺失都会弹窗阻断：

  • 未选择工程
  • FTP 未连接
  • 未选择目标包（主目标或嵌入目标）
  • 未勾选任何待更新文件（整包更新模式豁免）
  • 勾选了「更新版本记录」但任务和客服都为空
  • 勾选了「更新版本记录」或「执行备份」但开发为空

预检按钮不走此校验，仅输出日志，方便快速查看当前状态。

1.9 多主目标与备份冲突

多主目标

同一系统下若多个子目录存在同名 JAR（如 shared-edp/X.jar + shared-tms/X.jar），插件会自动识别并锁定所有同名包，每个独立备份 / 加锁 / 上传：

  • 备份路径按父目录分隔：backup/yyyyMMdd_{开发}/shared-edp/X.jar 和 backup/yyyyMMdd_{开发}/shared-tms/X.jar
  • 每个目标单独下载远端、独立打补丁、独立上传；内容不同的包互不干扰
  • 回滚时按路径逐一恢复

备份冲突处理

点击「打包并上传」时会自动查询：今天该开发人员是否已经备份过这些目标。如果有冲突，弹出选择对话框：

  • 覆盖备份：用当前远端包覆盖老备份。⚠ 上一版远端包将永久丢失。
  • 使用原始备份（推荐）：本次不重新备份，保留更早的备份作为回滚源。适合「同一天多次更新同一个包」的场景。
  • 新增备份目录：另建 yyyyMMdd_{开发}_v2 / _v3 / ... 目录，老备份完整保留。
💡 多次更新同一个包时建议取消勾选「执行备份」，用第一次的备份作为回滚来源。

1.10 更新记录格式

勾选「更新版本记录」后，上传成功时在远端同目录追加 *_update_notes.txt（复数），每次追加两行：

取包时间：20260417 21:00 开发：xumanyi 任务：【xxx】补丁 客服：20260417xxx 包名称：scev6-xxx.jar
传包时间：20260417 21:00 开发：xumanyi 任务：【xxx】补丁 客服：20260417xxx 包名称：scev6-xxx.jar

任务和客服至少填一项即可，未填字段保留标签、值为空。

1.11 常见问题

FTP 连接失败？

检查 VPN 是否连上、端口是否正确（默认 18080）。可以点「账号 ▾ → 添加新账号」重新输凭据。

预检通过但上传失败？

多半是目标包被别人加锁了。看日志里的锁文件名，联系对应的开发解锁，或等他更新完再试。

本地模式提示"版本号不匹配"？

源工程产物版本号必须和本地包版本号完全一致。scev6-utils-tms-10.0.0.jar 不能对 scev6-utils-tms-10.0.0-SNAPSHOT.jar 打补丁。

war 的 lib 里找不到目标 jar？

检查 war 是否是目标客户环境的，或 lib 里的 jar 名前缀是否一致。

同时更新多个包？

可以。JAR 更新时勾选多个 WAR 实现嵌入更新；多主目标场景下同名 JAR 会自动并行处理。

备份包在哪？

FTP 系统目录下 backup/YYYYMMDD_operator/。多个子目录的同名包会在备份目录下按原相对路径镜像保留。

第二部分：CLI 命令行使用

CLI 工具是独立的命令行版本，适用于自动化脚本、CI/CD 集成、或无 IDEA 环境的场景。功能上和插件完全对等：部署、备份、回滚、凭据管理，外加插件未直接暴露的「残留锁清理」。

2.1 环境准备

项目要求
JavaJDK 17 或以上，确保 java -version 可用
CLI 工具flux-deploy-cli.jar（约 3MB fat-jar，自包含所有依赖）
网络能访问目标 FTP 服务器

获取与部署

./gradlew :cli:shadowJar
cp cli/build/libs/flux-deploy-cli-1.1.2-all.jar ~/bin/flux-deploy-cli.jar

或设置环境变量 FLUX_DEPLOY_CLI 指向 jar 绝对路径。

2.2 子命令速查

子命令用途
deploy按 JSON 配置执行一次完整的 FTP 部署流水线
schema输出 deploy 配置的 JSON Schema，便于脚本或工具理解字段
credential管理本机凭据缓存：set / list / delete
unlock扫描并恢复残留锁文件（中断部署留下的 *__LOCK__*）
rollback从指定备份目录恢复 FTP 上的包

所有子命令都支持 --help / -h 查看详细参数。

2.3 凭据管理（credential）

CLI 自管凭据缓存，位置 ~/.flux-deploy/credentials.toml（文件权限 600，密码 AES-256-GCM 加密，密钥绑定当前机器和用户）。

首次配置（交互式输入密码）

java -jar ~/bin/flux-deploy-cli.jar credential set \
  --host 47.102.153.34 --port 18080 --user xumanyi
# CLI 提示: Enter password:（输入隐藏，不进 shell history）

查看与删除

# 列出所有条目（不显示密码）
java -jar ~/bin/flux-deploy-cli.jar credential list

# 删除指定条目
java -jar ~/bin/flux-deploy-cli.jar credential delete \
  --host 47.102.153.34 --port 18080 --user xumanyi

# 清空全部（直接删文件）
rm ~/.flux-deploy/credentials.toml
⚠ 拷贝到其他机器无法解密（密钥绑定本机），换机必须重新 credential set。

2.4 部署（deploy）

调用格式

java -jar ~/bin/flux-deploy-cli.jar deploy --config <json文件>
  [--password-file <密码文件>]   # 可选，覆盖缓存
  [--dry-run]                    # 可选，仅预检不改动远程
  [--verbose]                    # 可选，调试信息到 stderr

更新模式（mode 字段）

CLI 与插件 UI 一致，只支持两种更新模式：

mode含义必填字段CLI 编译
full（默认）整包替换，上传 localFile。CLI 不参与编译，由用户提前 mvn packagetargets[].localFile不编译
incremental下载远端包 → 按 files 打补丁 → 上传projectDir, files, targets[].name强制 mvn clean package -DskipTests

注意：

  • v1.1.2 起删除了原 mode=auto。"文件来源"（手选 / Git 检测）由调用方负责——插件 UI 用预填清单组件，Skill 用 git status 后向用户确认；CLI 不内置 git 检测。
  • v1.1.2 起删除了原 skipCompile 字段。incremental 模式必编译，避免 "改了源码忘编译就上线" 的事故。

JSON 配置字段

字段必填说明
ftp.host是纯 IP 或主机名，不含 ftp://
ftp.port否默认 18080
ftp.username是登录用户名，同时用作凭据缓存匹配键
remoteDir是FTP 登录后 cwd 的目标路径
mode否full / incremental，默认 full
projectDir条件incremental 模式必填，模块根（含 pom.xml）
files条件incremental 必填；条目示例 "M src/main/java/Foo.java"
mavenHome / javaHome否覆盖 mvn / JDK 路径（仅 incremental 用）
targets[].localFile条件full 模式必填；incremental 留空（CLI 自动生成）
targets[].name条件full 可省略（自动扫描）；incremental 必填
targets[].relativePath否远程相对路径；有多级目录时必填
meta.taskId / customerId / operator否版本记录相关；要求备份时 operator 必填
options.skipBackup否默认 false；想跳过备份时设 true
options.skipNote否默认 false；不写版本记录时设 true
options.outputFormat否json 或 text，默认 text

完整字段定义（含 embedTargets 等）用 2.5 schema 子命令获取。

示例 1：扫描模式，无备份无版本记录

cat > /tmp/deploy.json <<'EOF'
{
  "ftp":       { "host": "47.102.153.34", "port": 18080, "username": "xumanyi" },
  "remoteDir": "/开发/1测试项目/TMS V9.0-P7/",
  "targets":   [ { "localFile": "/path/to/scev6-utils-tms-9.0.0-SNAPSHOT.jar" } ],
  "options":   { "skipBackup": true, "skipNote": true, "outputFormat": "json" }
}
EOF
java -jar ~/bin/flux-deploy-cli.jar deploy --config /tmp/deploy.json

CLI 自动扫描 remoteDir 下所有 scev6-utils-tms-9.0.0-SNAPSHOT.jar 并并行更新。

示例 2：显式路径 + 备份 + 版本记录

{
  "ftp":       { "host": "47.102.153.34", "port": 18080, "username": "xumanyi" },
  "remoteDir": "/开发/AISKILL测试项目/TMS V9.0-P7/",
  "targets":   [ {
    "localFile": "/build/tm10srv.war",
    "name": "tm10srv.war",
    "relativePath": "tmssrv-1/tm10srv.war"
  } ],
  "meta":      { "taskId": "T-12345", "customerId": "C-67890", "operator": "xumanyi" },
  "options":   { "skipBackup": false, "skipNote": false, "outputFormat": "json" }
}

示例 3：增量模式（手动指定文件）

{
  "ftp":       { "host": "47.102.153.34", "port": 18080, "username": "xumanyi" },
  "remoteDir": "/开发/1测试项目/TMS V9.0-P7/",
  "mode":      "incremental",
  "projectDir": "/Users/xumanyi/scev6/v6_000_utils/scev6-utils-tms",
  "files": [
    "M src/main/java/com/flux/Foo.java",
    "M src/main/resources/log4j.xml"
  ],
  "targets": [ {

2.6 清理残留锁（unlock）

部署被中断时会留下 <pkg>__LOCK__<user>_<timestamp> 文件。LockGate 检测到残留锁会拒绝新部署，此时用 unlock 清理。

java -jar ~/bin/flux-deploy-cli.jar unlock \
  --host <host> --port <port> --user <user> \
  --remote-dir <path>
  [--delete-orphans]   # 活跃包已存在的孤立锁直接删除

恢复规则

  • 锁文件同目录无活跃包 → rename 回原名（恢复）
  • 锁文件同目录有活跃包 →
    • 不带 --delete-orphans：列为冲突并跳过（安全）
    • 带 --delete-orphans：直接删除孤立锁（确认活跃包是想要版本时才用）

2.7 历史回滚（rollback）

从指定备份目录恢复 FTP 包。全流程启用安全门禁：自动对当前状态再备份一份（方便"撤销回滚"）、加锁、上传备份内容、SHA256 校验、解锁。

java -jar ~/bin/flux-deploy-cli.jar rollback \
  --host <host> --port <port> --user <user> \
  --remote-dir <systemRoot> \
  --backup-dir <backupDirName> \
  [--operator <id>]         # 默认 rollback
  [--dry-run]                # 预览映射不实际修改
  [--no-safety-backup]       # 跳过对当前状态的再备份（不推荐）

行为

  1. 解析系统根（--remote-dir 前 3 级），拼出 <systemRoot>/backup/<backupDirName>/
  2. 递归扫描备份目录下所有文件
  3. 对每个文件，校验生产上对应路径是否存在；不存在则跳过并警告（不会新建孤立文件）
  4. 下载备份到本地临时目录
  5. 对当前生产状态做安全备份到 backup/<YYYYMMDD>_rollback_<HHmmss>/
  6. 走完整门禁（加锁/上传/校验/解锁）；失败自动回滚到回滚前

示例

# 先用 dry-run 看清楚要恢复哪些
java -jar ~/bin/flux-deploy-cli.jar rollback \
  --host 47.102.153.34 --port 18080 --user xumanyi \
  --remote-dir "/开发/1测试项目/TMS V9.0-P7/" \
  --backup-dir "20260424_xumanyi" \
  --dry-run

# 确认无误后正式执行
java -jar ~/bin/flux-deploy-cli.jar rollback \
  --host 47.102.153.34 --port 18080 --user xumanyi \
  --remote-dir "/开发/1测试项目/TMS V9.0-P7/" \
  --backup-dir "20260424_xumanyi" \
  --operator xumanyi
💡 回滚是高风险操作，强烈建议先 --dry-run 核对映射表；默认保留的安全备份让你可以在意外时"撤销回滚"。

2.8 本地打补丁（patch-local）

对应插件「本地模式」：用户手里有一个本地 jar/war 包，让 CLI 把源工程的变更打进去，输出新包。不登录 FTP、不备份、不写版本记录、不可回滚。

java -jar ~/bin/flux-deploy-cli.jar patch-local \
  --project-dir <模块根> \
  --local-package <本地 jar/war 路径> \
  --mode full|incremental|auto \
  [--files "f1,f2,..."]      # incremental 模式必填
  [--artifact-name <name>]   # 可选，默认从 pom.xml 推断
  [--git-root <path>]        # auto 模式可选
  [--output-dir <path>]      # 可选，默认 <包所在目录>/patched_<时间戳>/
  [--maven-home <path>] [--java-home <path>]

三种分流（自动判定）

  • jar → jar：源工程是 jar 模块，用户提供 jar 包；校验包名前缀+版本一致后替换 jar 内条目
  • war → war：源工程是 war 模块，用户提供 war 包；替换 WEB-INF/classes/ 下条目
  • jar → war/lib：源工程是 jar，用户提供 war 包；定位 WEB-INF/lib/ 下匹配的 jar，抽出 → 打补丁 → 回写

示例

java -jar ~/bin/flux-deploy-cli.jar patch-local \
  --project-dir /Users/xumanyi/scev6/v6_000_utils/scev6-utils-tms \
  --local-package /Users/xumanyi/Downloads/tm10srv.war \
  --mode auto

2.9 浏览 FTP（browse）

对应插件的项目/系统/包三级下拉。AI 不知道目标 FTP 有哪些项目/包时，先 browse 探一下。

# 列出指定目录下的子目录
java -jar ~/bin/flux-deploy-cli.jar browse \
  --host <host> --port <port> --user <user> \
  --list-dirs "/开发/1测试项目/"

# 递归扫描可部署包（JAR/WAR）
java -jar ~/bin/flux-deploy-cli.jar browse \
  --host <host> --port <port> --user <user> \
  --scan-packages "/开发/1测试项目/TMS V9.0-P7/"

输出 JSON 到 stdout，含每个包的 subDirectory / packageName / type / relativePath / size，可直接 | jq 解析。
