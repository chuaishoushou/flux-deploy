版本记录

v1.2.5 2026-04-28

修复

  • 批量备份多个 WAR 包时 FTP 421 断连：长时间传输大文件会让控制连接空闲过久，部分 FTP 服务端会关闭连接。本版为 FTP 传输启用控制连接保活，并将批量备份中的目录创建、下载、上传、大小校验拆成短连接执行，避免一个长连接在多包备份过程中被踢掉。
  • Marketplace 2024.1.7 兼容性校验：补充 Java 模块依赖声明，修复使用 JavaSdk / JavaSdkVersion 但未声明 com.intellij.modules.java 导致的兼容性问题。
v1.2.4 2026-04-27

优化

  • 编译 JDK 按 pom 自动匹配：原先固定用 Project SDK（全工作空间共用，切分支不同步）。现在按模块 effective pom 的 release / target / source 在 IDEA 全局 SDK 表中精确匹配；匹配不到直接报错，不向上回退；pom 未声明则沿用 Project SDK。日志带 [编译][JDK] 前缀。

修复

  • 兼容 IDEA 2024.2+ MavenProject API 变更：getReleaseLevel / getTargetLevel / getSourceLevel 被移除导致 NoSuchMethodError，已兼容，跨 2024.1 ~ 2025.x 可用。
  • FTP「打包不上传模式」：增量更新下，本地产物改为与 FTP 上传同源（staging / aligned 包，WAR 嵌入走 patchExistingJar），包内未变更条目保留远端原始时间戳。
  • FTP「部署目标」主目标支持取消勾选：客户备份目录命名不规范（如 yyyyMMdd 等非 backup 关键字目录）时，SCAN_SKIP_DIRS 兜不住，备份包会被当作主目标锁定且无法取消；现移除"锁定不可取消"约束（默认仍勾选 + 加粗显示），用户可手动取消任意目录下的包。
v1.2.3 2026-04-27

修复

  • FTP「部署目标」扫描会把备份目录下的历史包当作主目标列出：在已存在 backups/{YYYYMMDD}_{user}/ 等目录的客户环境上，UI 会把这些备份包勾成主目标，存在被覆盖写的风险。core 中扫描跳过列表 SCAN_SKIP_DIRS 原本只在 CLI 校验路径生效，UI 浏览路径自带一份不完整的硬编码黑名单（仅 backup / bak）；现统一为单一真相源 {backup, backups, bak, .backup, .flux-lock}，CLI 与 UI 共用，避免漂移。
v1.1.2 2026-04-25

架构优化

  • 工程拆分为多模块：原单工程 flux-deploy-plugin 拆成 core / plugin / cli 三个 Gradle 模块。core 是纯业务（不依赖 IntelliJ Platform），plugin 仅做 IDEA 插件壳，cli 输出独立 fat-jar。代码级 156 处 IntelliJ import 编译期保证只在 plugin 模块——再也不会"误把 IDE 类打进 CLI"。
  • 恢复 CLI 入口：cli/build/libs/flux-deploy-cli-1.1.2-all.jar 约 776KB，含完整业务代码 + commons-net + Gson；可直接 java -jar 调用。子命令：deploy / schema / credential / unlock / rollback / patch-local / browse。
  • 新增 AI Skill：flux-customer-service-update，让 LLM 通过 CLI 完成客服更新；密码全程不经过 AI（由 CLI 内部从 ~/.flux-deploy/credentials.toml 读取并 AES-256-GCM 解密）。

UI 简化

  • 更新模式三档合并为两档：整包更新 / 手动选择 / 自动检测变更 → 整包更新 / 增量更新。「文件来源」（手选 / Git 检测）不再是模式选项，而是同一个增量模式下的预填方式：进面板默认按 Git 变更勾选，用户可任意增删。原来三个模式互斥，现在能"在 Git 默认基础上调整"——更灵活。
  • 右键菜单「自动检测」「手动选择」两个入口保留，但都进入新的「增量更新」模式，只是预填方式不同。
  • 插件 ZIP 600KB（基本不变）；CLI fat-jar 776KB（含全部业务代码 + 第三方依赖）。

CLI Schema 简化

  • 删除 mode=auto（合并进 incremental）；CLI 不再内置 git status 检测，"文件来源"由调用方负责。
  • 删除 skipCompile 字段；incremental 模式强制 mvn clean package，避免"改了源码忘编译就上线"。
  • 删除 gitRoot 字段。
  • schema 子命令（v1.1.1 引入）输出的 JSON Schema 反映新约束，AI Skill 可实时加载。

v1.0.8 2026-04-19

新增

  • 备份冲突三选项策略：点击「更新 FTP」检测到当天已有备份时，弹出处理方式对话框，可选：
    • 覆盖备份：用当前远端包覆盖老备份（原始远端包将永久丢失）
    • 使用原始备份（推荐）：本次不备份，保留更早的备份作为回滚源
    • 新增备份目录：并行建 yyyyMMdd_{开发}_v2 / _v3 / ... 目录，两份备份都保留
  • 多主目标支持：同系统下同名 JAR 分散在不同子目录（如 shared-edp/X.jar + shared-tms/X.jar）时，会自动识别并独立备份 / 加锁 / 上传每一个；备份路径按父目录自动分隔为 backup/yyyyMMdd_{开发}/{子目录}/X.jar。
  • 内部类残留清理：修改主类时，若原远端包含有 Foo$N.class 而本地编译产物中已不存在（重构时删掉了某个内部类），会自动将残留条目从输出包中清理，避免运行时 NoClassDefFoundError。
  • 编译前自动保存 IDE buffer：编译前调用 FileDocumentManager.saveAllDocuments()，消除"改了代码没保存导致 mvn 读旧源码"的顽固问题。
  • 编译后产物校验：打印产物大小与 mtime；若 mtime 早于 mvn 启动时间，输出警告（可能 pom finalName 不对 / mvn clean 失败）。
  • 本地打包确认对话框：FTP 模式下点击「本地打包」会弹出确认框，列出目标包与执行计划，避免误点。
  • 源工程选择弹窗：加搜索框：在工程树上方加入搜索框，输入时切换为扁平列表、显示每个模块的父路径，支持 artifactId 和父目录名关键字匹配。
  • 自动化测试套件：
    • ./gradlew runLocalModeTest：本地模式 3 场景 × 3 模式全自动回归
    • ./gradlew runFtpModeTest：FTP 模式 3 种 DeployMode 全自动（自建测试目录、自清理）
    • ./gradlew runAllE2ETests：一键跑全部
  • 失败总结卡片：部署失败后日志末尾统一输出 ❌ 部署失败 卡片 + 原因，避免用户往上滚才能定位失败点。

优化

  • 日志格式整体改版：
    • 消息内嵌 \n 会自动拆行，每行独立带时间戳，空段转为无前缀空行做视觉分隔。原先的 banner 错位问题（╔══╗ 不带时间戳）已修复
    • 部署开始不再清空日志，追加 ────── 开始新一轮部署 ────── 分隔线，保留前置检查上下文
    • 所有用户动作加 [操作] 前缀日志：按钮点击、对话框确认/取消、策略选择都留痕
    • mvn 输出去除 -q 确保 BUILD SUCCESS 可见；增加 mvn 退出码 日志
    • 备份冲突检测：每个目标路径都打印查询结果 [备份检查] ✓ 已存在 ...
    • 去除重复 开始预检... 输出
  • 本地模式多版本 lib 精确选择：当 WAR 的 WEB-INF/lib/ 下同时存在同前缀多个版本（如 scev6-utils-tms-9.0.0.jar 和 10.0.0.jar）时，自动挑选版本与源产物一致的那个做替换；老版本不受影响。相应的 WarEmbedUtil.embedJar 也改用完整包名做精确前缀。
  • 回滚：递归清理空备份子目录：多目标备份形成的 backup/日期_开发/子目录/子子目录/X.jar 结构，回滚后自底向上递归清理所有空目录。
  • 重置按钮行为对齐：本地模式重置按钮现在和 FTP 模式一致，同步清空源工程、本地包路径、日志、预检状态。
  • 本地模式支持整包更新：新增三种场景的 FULL 分流：
    • jar → jar：新产物整体覆盖
    • war → war：新产物整体覆盖
    • jar → war/lib：新 jar 精确替换 WAR 内匹配版本的 lib jar
  • WAR lib 对齐产物校验：FULL + WAR 模式的 alignWarLibs 产物做 size / 存在性校验，异常立即终止而非传给后续阶段。
  • 更新模式感知的刷新：点击更新模式旁刷新按钮时，INCREMENTAL 模式下保留用户已勾选且仍存在的文件；AUTO_DETECT 重跑 Git；FULL 输出提示。

修复

  • 多目标 FTP 部署 "包还是旧的" / 550 File not found：之前多目标重构把暂存包构建移到了加锁之后，加锁会把远端原文件 rename，导致后续下载 550；已改为加锁前预构建每个目标的产物并缓存。
  • 多目标嵌入阶段 mainOffset 错位：lockedPackages.get(ei + mainOffset) 在多主目标下会取到错误的锁信息；改为 mainOffset = mainTargets.size()。
  • USE_EXISTING 策略下回滚会误删老备份：借用已有备份作为回滚源时，rollback 后不再清理该备份（否则后续再次 USE_EXISTING 找不到回滚源）；manualRollback 同步处理。
  • 凭据解密 Tag mismatch：命令行测试启动时 user.name 与 IDE 运行时不同导致密钥派生不匹配；测试 gradle 任务已锁定 user.name=xumanyi 规避。
